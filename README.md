# Вариант задания

## Язык программирования

**Kotlin**.

В лабораторной работе рассматривается грамматика арифметических выражений, включающая:

- идентификаторы;
- целые числа;
- бинарные арифметические операции;
- круглые скобки для изменения порядка вычислений.

## Контекстно-свободная грамматика

Грамматика арифметических выражений имеет следующий вид:

```text
E → T A
A → ε | + T A | - T A
T → F B
B → ε | * F B | / F B | % F B
F → num | id | (E)

id  → letter {letter | digit | _}
num → digit {digit}
```

## Формальное определение грамматики

Грамматику можно задать как:

```text
G[E] = {Vt, Vn, E, P}
```

где:

```text
Vt = {
    id, num, +, -, *, /, %, (, )
}
```

```text
Vn = {
    E, A, T, B, F
}
```

Начальный символ:

```text
E
```

Множество правил продукции:

```text
P = {
    E → T A,
    A → ε,
    A → + T A,
    A → - T A,

    T → F B,
    B → ε,
    B → * F B,
    B → / F B,
    B → % F B,

    F → num,
    F → id,
    F → (E)
}
```

## Классификация грамматики

Данная грамматика является **контекстно-свободной**, так как в левой части каждого правила продукции находится ровно один нетерминальный символ.

Для синтаксического анализа используется метод **рекурсивного спуска**. Каждому нетерминалу грамматики соответствует отдельная процедура:

```text
E → ParseE()
A → ParseA()
T → ParseT()
B → ParseB()
F → ParseF()
```

Приоритет операций задаётся структурой грамматики:

- операции `*`, `/`, `%` обрабатываются на уровне нетерминала `T`;
- операции `+`, `-` обрабатываются на уровне нетерминала `E`;
- скобки обрабатываются в правиле `F → (E)`.

За счёт этого операции умножения, деления и остатка от деления имеют более высокий приоритет, чем сложение и вычитание.

## Примеры корректных строк

```text
12 + 5
12 + 5 * 3
(12 + 5) % 3
a + b * c
(x + 10) / y
a_b12 + 25 * (c3 - 4)
```

# Лексический анализ

## Назначение лексера

Лексический анализатор выполняет посимвольный просмотр входной строки и выделяет лексемы арифметического выражения.

На этапе лексического анализа распознаются:

| Лексема | Описание |
|---|---|
| `id` | идентификатор |
| `num` | целое число |
| `+` | операция сложения |
| `-` | операция вычитания |
| `*` | операция умножения |
| `/` | операция деления |
| `%` | операция остатка от деления |
| `(` | открывающая круглая скобка |
| `)` | закрывающая круглая скобка |

Идентификатор начинается с буквы и может содержать буквы, цифры и символ `_`.

Целое число состоит из одной или нескольких цифр.

# Синтаксический анализ методом рекурсивного спуска

## Назначение парсера

Синтаксический анализатор проверяет, соответствует ли последовательность лексем заданной контекстно-свободной грамматике.

В программе реализован синтаксический анализ методом рекурсивного спуска. Для каждого нетерминала грамматики используется отдельный метод:

| Нетерминал | Метод |
|---|---|
| `E` | `ParseE()` |
| `A` | `ParseA()` |
| `T` | `ParseT()` |
| `B` | `ParseB()` |
| `F` | `ParseF()` |

Общий порядок анализа:

1. Выполняется лексический анализ входной строки.
2. Если лексических ошибок нет, запускается синтаксический анализ.
3. Разбор начинается с начального нетерминала `E`.
4. Если выражение корректно, формируется внутреннее дерево выражения.
5. Если обнаружены ошибки, они выводятся в таблицу результатов.

# Внутренняя форма представления программы: тетрады

## Назначение тетрад

Тетрады используются как внутренняя форма представления арифметического выражения.

Каждая тетрада имеет вид:

```text
(op, arg1, arg2, result)
```

где:

- `op` — операция;
- `arg1` — первый операнд;
- `arg2` — второй операнд;
- `result` — временная переменная, в которую помещается результат операции.

В программе временные переменные имеют вид:

```text
t1, t2, t3, ...
```

Тетрады строятся только для корректных выражений, в которых отсутствуют лексические и синтаксические ошибки.

## Пример построения тетрад для выражения из целых чисел

Исходная строка:

```text
(12 + 5) % 3
```

Ожидаемая последовательность тетрад:

```text
(+, 12, 5, t1)
(%, t1, 3, t2)
```

## Пример построения тетрад для выражения с идентификаторами

Исходная строка:

```text
a + b * c
```

Ожидаемая последовательность тетрад:

```text
(*, b, c, t1)
(+, a, t1, t2)
```

Данный пример показывает, что тетрады могут быть построены для корректного арифметического выражения с идентификаторами.

# ПОЛИЗ

## Назначение ПОЛИЗ

ПОЛИЗ — польская инверсная запись, в которой операция записывается после своих операндов.

Например, инфиксное выражение:

```text
12 + 5
```

в ПОЛИЗ записывается как:

```text
12 5 +
```

В программе ПОЛИЗ формируется только для корректных арифметических выражений, состоящих исключительно из целых чисел.

Если выражение содержит идентификаторы, вычисление невозможно, так как значения переменных неизвестны.

## Пример построения ПОЛИЗ и вычисления выражения

Исходная строка:

```text
(12 + 5) % 3
```

Построенная ПОЛИЗ:

```text
12 5 + 3 %
```

Пошаговое вычисление:

```text
12 5 + 3 %

1. 12 помещается в стек: [12]
2. 5 помещается в стек: [12, 5]
3. выполняется операция 12 + 5 = 17: [17]
4. 3 помещается в стек: [17, 3]
5. выполняется операция 17 % 3 = 2: [2]
```

Результат вычисления:

```text
2
```

![ПОЛИЗ: построение и вычисление](images/lab6-poliz-evaluate.png)

## Пример вычисления с приоритетом операций

Исходная строка:

```text
12 + 5 * 3
```

Построенная ПОЛИЗ:

```text
12 5 3 * +
```

Результат вычисления:

```text
27
```

Данный пример подтверждает, что операции `*`, `/`, `%` имеют более высокий приоритет, чем операции `+` и `-`.

![ПОЛИЗ: проверка приоритета операций](images/lab6-poliz-priority.png)

## Пример запрета ПОЛИЗ для выражения с идентификатором

Исходная строка:

```text
a + 5
```

Ожидаемый результат:

- лексический анализ завершается успешно;
- синтаксический анализ завершается успешно;
- выражение корректно с точки зрения грамматики;
- ПОЛИЗ и вычисление не выполняются, так как по заданию ПОЛИЗ формируется только для выражений из целых чисел.

![ПОЛИЗ: выражение с идентификатором](images/lab6-poliz-identifiers-warning.png)

## Пример ошибки вычисления: деление на ноль

Исходная строка:

```text
12 / (3 - 3)
```

Построенная ПОЛИЗ:

```text
12 3 3 - /
```

При вычислении выражения возникает деление на ноль.

![ПОЛИЗ: деление на ноль](images/lab6-poliz-division-by-zero.png)
